# 三个Case测试

## 最新：锁定后不再因2秒杯子识别超时而暂停

首次锁定仍要求杯子置信度≥0.30、连续3次识别确认，锁定后等待1秒。
锁定后，只要当前帧通过CSRT/光流定位及原有位置、大小、外观检查，就持续反馈。
保留每约0.5秒的局部杯子识别作为辅助校正，但其漏检或低置信度不会单独使有效视觉跟踪超时。
真正视觉定位失败、出画面、相似目标身份有歧义或画面尺寸改变时仍暂停。
不使用预测位置代替当前图像定位，不更换原目标；750ms画面新鲜度和固件通信停止保护不变。
这会减少因分类漏检造成的暂停，但视觉跟踪仍可能漂移或失败，不保证永不丢失。
Case2、gap0.3秒及其他Case不变。仅需退出并重启电脑程序，无需重新上传Arduino。
以下历史内容中的“2秒语义校验超时停止”不再适用。


## Showcase默认方案：Case 2，gap 0.3秒

双击“启动相机振动引导.command”，或运行：

```bash
./.venv/bin/python sony_wifi_yolo.py --testing --haptics-port /dev/cu.usbserial-0001
```

启动不再询问Case，默认Case2、gap0.3秒。仅指定--haptics-port时也默认此方案。
扫描确认水杯后锁定，等待1秒，再按位置偏差给出1/3/5次脉冲，强度70、每次ON200ms、间隔300ms。
完整目标框进入中央区域时停止；跟踪丢失、坐标过期和通信超时的停止保护保持不变。
--testing模式保留终端1/2/3切换Case、gap 0.1/0.3/0.5调整间隔、0暂停、start继续、r重选、q退出。
切换Case/间隔仍会清除目标，自动重新锁定并等待1秒。输入2不会自动恢复gap0.3，若改过间隔请再输入gap 0.3。
“启动三个Case测试.command”保留启动询问流程（--choose-case），默认选项也改为Case2。
命令行--haptics-case 1或3、--pulse-gap仍可覆盖默认设置。
本次只改电脑程序，不改Arduino固件，无需重新上传。


## 最新：移动中连续定位与有界容错

初次锁定仍是置信度0.30、连续3次推理确认，再等待1秒。
锁定后逐帧CSRT定位；前后帧的局部光流可在CSRT短暂失败时提供独立的当前图像位置。
校正搜索区域随当前可信位置移动，不再强制跟随旧的检测锚点。
单次YOLO校验失败时，若当前图像仍有可靠跟踪，最多允许2秒语义确认间隔，继续反馈。
两秒内仍未再次确认、视觉定位真正失败、出画面或多杯身份有歧义时暂停，不伪造连续位置。
运动外推仅用于最多0.75秒的局部寻找，不用于输出坐标或驱动马达；光流只有当前图像匹配成功才可输出。
界面及headless JSON的tracking_diagnostics显示跟踪来源、校正失败原因和状态。
连续移动仍可能受模糊、遮挡、杯子纹理及检测误判影响；本地生成画面测试不是实机准确率证明。
750ms固件通信超时与画面新鲜度检查保持不变；不靠重复发送旧方向维持震动。
本次不改Arduino和硬件接线，重启电脑程序生效。
以下“一次校正失败立即停止”的历史说明已被本节替代。

## 最新：连续确认＋低频局部校正

自动水杯模式已改为混合跟踪，不再使用“单帧识别一次后完全不核对”的规则。
- 初次锁定默认要求置信度≥0.30、连续3个推理帧位置/大小一致；两个模型重复框只算一次。
  初次候选优先置信度较高者；低分或断检会重新累计，连续推理帧不代表相机原始帧率。
- --cup-confidence 0.10仍是扫描门槛；--lock-confidence 0.30是更严格的确认/校正门槛。
- 连续确认后仍等待1秒，才允许三个Case反馈。
- CSRT在中间帧跟随，每约0.5秒仅在上一次可靠目标附近运行水杯核对。
  校正同时检查位置、宽高比例、初次外观；不搜索整幅画面来换目标。
- 未匹配、相似候选有歧义、跟踪失败或画面尺寸改变时暂停反馈，不使用旧坐标。
  原目标附近出现可靠匹配后可校正跟踪；极快移动或长时间遮挡可能仍需R重置。
- 外观和位置匹配是启发式规则，不能保证物理身份永不混淆，也不能保证消除所有误检。
- 终端模拟/真实反馈、三Case、中央入区条件和750ms超时停止不变，无需上传Arduino。

推荐先只放一只杯子、不接硬件：

```bash
./.venv/bin/python sony_wifi_yolo.py --cup-target --cup-confidence 0.10 --lock-confidence 0.30 --lock-frames 3
```

先确认界面出现1/3→2/3→锁定等待1秒，再缓慢移动；遮挡时应暂停，远处另一只杯子不应接管。
如果真实杯子始终分数不足0.30，会一直等待确认；应先改善光线/杯子尺寸，再有控制地比较阈值。
以下单次识别不校正的内容是历史说明，以上规则为准。

## 最新：识别一次，锁定后用CSRT跟踪物体

自动水杯模式现在分成两段：
1. 尚未锁定：YOLO/YOLOE按--cup-confidence持续检测水杯，不再依赖BoT-SORT跟踪ID。
2. 首次锁定：把当前框交给CSRT视觉物体跟踪器；等待1秒后允许方向反馈。
   此后不会调用YOLO重新识别、不会根据新的杯子置信度删掉目标、不会自动换杯子。

框旁`CSRT init=0.xx`是最初杯子识别分数，不是当前帧分类置信度，也不是跟踪准确率。
CSRT按当前图像更新物体框，坐标与入区判断仍按原图计算。
完全遮挡、目标出画面、画面尺寸改变或跟踪器明确失败时暂停反馈；不沿用旧坐标驱动马达，
也不会为了恢复而自动重扫。跟踪器可能恢复，也可能漂移或无法恢复，不能保证永久正确锁定。
需要明确重选时按R；R/切换Case会清除视觉跟踪，重新进行首次杯子扫描。
新流程需opencv-contrib-python 5.0.0.93，已在当前项目虚拟环境安装。
电脑端改动无需重传Arduino；不带硬件参数的命令仍只显示模拟反馈。
此规则替代历史的“每帧依赖杯子跟踪编号”规则。手动模式保留旧流程。

## 最新：第一次锁定后保持同一目标

锁定前一直扫描；第一次自动锁定后等待1秒，之后保持同一跟踪ID。
取消“丢失1秒后释放旧ID、自动选择另一只杯子”的逻辑。
丢失时停止反馈且不使用旧坐标；找回原ID后继续，不再次倒计时。
只有在初次1秒等待尚未完成就丢失时，找回后重新等待1秒。
原ID不再出现时会保持等待，不承诺通过ID判断真实物体身份永不出错。
R/终端r可以明确释放锁定并重新自动选杯子；切换Case仍会重置本次试验。
以下“丢失后自动重新选目标”的历史说明已被本节取代。

## 持续扫描与无硬件测试（最新）

水杯自动模式会不断扫描，首次一直没检测到也不需要R。
锁定目标丢失时立即停止反馈；先等待原跟踪ID，丢失满1秒自动释放旧ID，
从当前杯子中重新选择靠近中心的一只，再等待1秒才允许反馈。
因此丢失后可能换成另一只杯子；测试建议画面中仅放一只杯子。
原有“锁定后绝不换ID”的说明仅适用于手动模式/丢失不足1秒的情况。

不连接ESP32、不打开串口：

```bash
./.venv/bin/python sony_wifi_yolo.py --cup-target --cup-confidence 0.10
```

界面及终端显示模拟反馈：扫描中、已锁定等待1秒、模拟上/右/下/左、停止。
它不会实际震动，且保留画面新鲜度检查；推理太慢时显示超时停止。
测试：空画面等待后放入杯子→自动锁定→1秒后显示方向；遮住杯子→停止；
移开遮挡→自动重新锁定→1秒后恢复方向。完整入中央框则停止。
不加`--testing`或`--haptics-port`，以免尝试连接硬件。Q/Esc退出。

## 2026-10-30：自动锁定，1秒后启用反馈

现在`--testing`/`--cup-target`默认取消1.5秒稳定等待和手动点击，立即开始识别。
首次找到水杯后自动锁定离画面中心最近的一只（归一化中心距离），等待1秒。
只有随后新鲜识别仍确认同一跟踪目标、且未完整入区时才开始震动；入区则保持停止。
同一杯子一直跟踪，不会因另一个杯子更近而切换；丢失立即停止，不替换其他杯子。
原杯子找回后重新等待1秒；R或终端r可重置并自动选择新目标。
Case切换/间隔切换也重新锁定并等待1秒。1秒是锁定后的等待时间，不包含模型启动及推理时间。
若需恢复旧手动流程，启动命令加`--manual-target`。
本次仅改电脑端，无需重新上传Arduino，Case1/2/3、中央框完成规则、750ms超时停止不变。
以下旧说明中的“稳定1.5秒/点击选择”仅适用于`--manual-target`。

## 新增：Sony水杯＋中央目标区域（整合上游e7725bb）

`--testing`现在默认启用水杯区域测试，也可用`--cup-target`单独启用。
只识别水杯，仍需稳定1.5秒后点击选中，并持续跟踪同一只杯子；丢失不改选其他杯子。
黄色中央框是实验目标区，不是人工标注的ground-truth框。
源规则为1920×1080画面中的500×750竖框；Sony适配使用统一缩放系数
`min(原图宽/1920, 原图高/1080)`，例如640×480对应约166.7×250，保持竖框比例。
整个水杯检测框（含边界）进入区域后框变绿、所有Case停止，不再以原3%中心容差判断完成。

水杯过大装不进区域时只提示后退/缩小画面，方向震动停止；没有水杯或丢失也停止。
界面的`cup_guidance`及headless JSON包含目标区域、完整入框结果、方向和提示。
旧的不带`--testing`和`--cup-target`的Sony入口仍保留人/树/水杯及3%中心容差。

依赖和模型沿用现有 `.venv` 及两个本地模型，不需要重新下载。

Sony打开智能遥控，Mac连接DIRECT热点，ESP32保持USB连接。

## 一致条件与Case区别

- 偏差不是现实距离：取目标框中心相对画面中心的 `max(abs(X)/宽, abs(Y)/高)`。
- 小偏差 <10%；中偏差 10%至<25%；大偏差 >=25%。
- 旧模式居中容差为宽高各3%、最低8px，退出有1.3倍滞回；水杯区域模式改用上面的完整入框条件。
- 斜向两个模块同步反馈，使用同一最大轴偏差分级。
- Case1：持续反馈，强度小/中/大=40/70/100。
- Case2：固定强度70，小/中/大=1/3/5次；每次ON 200ms；OFF间隔100/300/500ms。
  1次组内无间隔；每组结束后OFF 1000ms，目标仍偏离则重复。相同心跳不会重启脉冲组。
  方向、偏差档位或参数改变会取消旧组并立刻按新条件开始；居中/目标丢失即停止。
- Case3：固定70持续反馈，直到居中。
- 选目标前的平移容差由4%放宽至8%；图像差异阈值也适度放宽。
  参考帧仍固定，明显移动仍重置；锁定后原本就不再要求稳定等待。
- 未选目标、丢失目标、暂停、退出、无新鲜画面时不驱动；750ms固件看门狗保留。
- 默认不带--testing/--haptics-case的旧入口保留旧方向开关模式。

非交互固定条件启动（每次退出后可换参数）：

```bash
./.venv/bin/python sony_wifi_yolo.py --cup-target --haptics-port auto --haptics-case 1
./.venv/bin/python sony_wifi_yolo.py --cup-target --haptics-port auto --haptics-case 2 --pulse-gap 0.1
./.venv/bin/python sony_wifi_yolo.py --cup-target --haptics-port auto --haptics-case 3
```

RTP数值不是电压或感知强度百分比。测试前检查马达额定参数及供电；斜向可能同时驱动两个马达。
这些设置没有自动统计用户方向判断准确率、主观舒适度或任务完成时间，需实验员记录。
无实体相机、马达时通过单元测试不等于实际效果验证；新增固件必须重新上传。
